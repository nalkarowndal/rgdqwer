# M1 이미지 생성 설계

사용자의 '시작' 지시에 따라 기존 M0 위에 실행 가능한 이미지 생성 경로를 추가한다.
M0 Windows 실기 및 실제 GPU 검증은 미완료이며 M1 구현/모의 QA와 별도 게이트로 유지한다.

## 범위

SD1.5(512 기본, 최대 768), SDXL/Illustrious(1024 기본/최대), 배치 1.
파일명으로 모델 계열을 추측하지 않고 사용자가 호환 프로필을 선택한다.
Anima/Krea/LoRA는 별도 워크플로가 필요하므로 이번 실행 어댑터에서 제외한다.
프롬프트/negative/seed/steps/CFG/크기를 저장하고 euler/normal 표준 노드를 사용한다.
한국어 자동 번역과 3개 입력 모드는 M2다.

## 흐름

입력 검증 → DB preparing → 노드·체크포인트·큐 확인 → API JSON 제출 →
WebSocket progress + history/queue polling → PNG 다운로드/디코딩 검증 → 파일 및 메타데이터 저장.
실제 엔진 없이 성공 결과나 진행률을 만들어 표시하지 않는다. 백분율은 샘플러 단계이며 전체 시간 예측이 아니다.
앱에는 한 작업만 활성화한다. 외부 ComfyUI 작업이 있으면 새 제출을 거절한다.

## 안정성

client_id 및 prompt_id를 앱 UUID로 지정하고 제출 전에 DB에 남긴다.
응답 손실/네트워크 실패는 상태 미확인으로 표시하며 자동으로 다시 제출하지 않는다.
재시작 시 기존 작업을 다시 추적한다. 종료는 원격 작업을 임의 취소하지 않는다.
취소는 POST /api/jobs/{prompt_id}/cancel만 사용한다. 404/405면 미지원 안내.
전역 /interrupt, 전체 큐 삭제, 메모리 강제 해제를 호출하지 않는다.
종료/실패 후에도 설정·시드·engine URL·작업 ID를 보존한다.

## 파일/보안

기존 Bearer/Origin 보호를 모든 신규 API에 적용한다. 결과는 인증된 fetch로 blob 표시/다운로드.
SaveImage의 앱 전용 rgdqwer 하위 경로와 해당 작업 파일만 수집한다.
다운로드 20MiB 제한, 요청한 크기의 PNG만 디코딩·CRC 검증 후 UUID.png로 원자적 저장.
정상 파일 저장 후 DB 완료 처리. 실패한 파일은 완료 결과로 표시하지 않는다.

## 완료 증거

실제 HTTP+WebSocket 모의 엔진으로 제출 payload, 진행률, 결과 PNG/DB 복구, 실패,
취소 범위, 외부 큐 보호, 재시작 추적, 응답 손실, 손상 PNG 및 인증 테스트.
브라우저에서 생성→결과→다운로드→라이브러리→재사용을 검사.
실제 ComfyUI/GPU 출력은 별도 실기 검증 전까지 미검증으로 보고한다.
