# M5 영상 스튜디오 설계

마스터 요구사항 §5/영상 프롬프트/M5에 따라 기존 로컬 Electron·React·Fastify 앱에 Wan2.2 TI2V5B 생성과 FFmpeg 변환을 연결한다. 반복된 시작 지시에 따라 기존 스택·단계별 구현 방식을 유지하고 아래 세부 선택은 구현자 판단으로 기록한다.

## 접근 방식과 범위

공식 ComfyUI 5B T2V/I2V API 그래프를 기존 단일 GenerationManager에 추가한다. 기본 AI V2V는 검증된 MP4를 FFmpeg로 제한된 프레임으로 정규화 → LoadVideo/GetVideoComponents/VAEEncode → denoise<1 KSampler의 명시적인 실험 어댑터로 제공한다. FFmpeg 변환/프레임 추출은 별도 모드로 실제 CPU 실행하며 AI 재생성으로 표시하지 않는다. 독립 Wan Python 엔진과 임의 custom-node/workflow 설치는 메모리 소유권과 의존성을 중복시켜 제외한다. 고급14B·RIFE·AI 초해상도는 M5 기본 경량 흐름에 포함하지 않는다.

## 입력·출력 계약

- VideoInput profile=wan22|video-tools, mode=t2v|i2v|v2v|convert|extract. 공통 모델/프롬프트/seed/steps/cfg/width/height와 textEncoder/vae, frames,fps,denoise,lowVram,sourceId,startSeconds,interpolation(none|motion),fit(contain|cover),includeAudio,8개 promptFields를 보존한다. mode/profile 조합을 엄격히 검사한다. 입력 내용에 따라 코드를 실행하지 않는다.
- AI 크기256..1280,32배수,전체901120픽셀 이하,프레임5..121/4n+1,fps1..30,steps1..50,cfg1..10, t2v/i2v denoise1,v2v .05..95. 기본640x384/33frames/24fps/20steps/CFG5. 저VRAM 선택은 CPU인코더를 실제 적용하고 해상도/프레임은 버튼으로 권장값 적용. Comfy --lowvram 옵션은 안내만 한다.
- tools 크기32..1280/32배수/921600픽셀 이하,프레임1..300,fps1..60,최대10초. Lanczos 크기조절/contain padding 또는 cover cropping/FPS 변환/선택적 motion interpolation/minterpolate/프레임PNG 추출. AI 업스케일링이나 AI 보간이라는 주장을 하지 않는다. 오디오는 변환 모드에서 명시적으로 선택한 경우만 AAC로 포함.
- 업로드는 인증된 binary POST /api/media/image|video, 이미지 PNG<=5MiB(기존 엄격CRC/디코드),영상 MP4<=32MiB(최대1920x1080/30초/60fps, H264 단일 영상 스트림). 서버 발급 UUID와 고정 확장자만 디스크 경로에 사용. 이미지/영상 미디어 metadata를 SQLite v4 media_inputs 테이블에 저장. 원본은 앱의 inputs 폴더에 보존하며 나중에 기록 재사용 가능. 미참조 업로드 삭제 API 제공.
- Artifact는 이전 PNG와 호환되는 optional mediaType/frames/fps/duration으로 확장. Job.kind video와 input union,workflowVersion wan22-v1|ffmpeg-v1. 출력MP4의 크기/FPS/프레임/codec/실제전체디코드를 검사 후 atomic 저장. 이미지 추출은 기존PNG검사. 결과artifact와입력파일path는 서버가 소유.

## 공식 그래프와 호환성

공식 video_wan2_2_5B_ti2v 템플릿: UNETLoader(default), CLIPLoader(wan), VAELoader(wan2.2), ModelSamplingSD3(shift8), positive/negative CLIPTextEncode, Wan22ImageToVideoLatent(배치1), KSampler(uni_pc/simple),VAEDecode,CreateVideo,SaveVideo(H264/MP4,id9). I2V에만 LoadImage/start_image 추가. 최신 SaveVideo dynamic format.codec와 기존 format/codec combo를 실제object_info로 구분한다. V2V에는 normalized MP4의 LoadVideo/GetVideoComponents/VAEEncode를 사용하며 추가 AI 품질 실기 게이트로 표시한다.

모델 파일: wan2.2_ti2v_5B_fp16.safetensors, umt5_xxl_fp8_e4m3fn_scaled.safetensors, wan2.2_vae.safetensors. 실제 loader 선택지와 필요한 노드·콤보를 제출 전 재검사. 원격 모델 자동 다운로드 없음. Comfy의8GB offload 안내와 독립 Wan CLI의24GB예시는 다른환경이며2060SUPER지원으로 단정하지 않는다.

## 미디어 처리·안전 경계

FFmpeg/ffprobe는 PATH 또는 operator 환경변수 STUDIO_FFMPEG/STUDIO_FFPROBE에서 찾는다. shell=false,고정인자,외부입력에서프로그램/필터/경로생성금지. mov강제demux,protocol file/pipe 제한,enable_drefs0/use_absolute_path0,입출력크기/timeout/스레드/stdout/stderr 상한. subprocess는 취소/앱종료시 종료하고 부분출력 제거. 종료·timeout이면 성공을 가장하지 않는다. MP4 이외playlist/외부참조콘텐츠를 허용하지 않는다.

업로드 정규화와 결과 검사는 FFmpeg가 필요하다. 누락이면 구체적인 설치안내를 제공하며 기본이미지/Krea는 계속 작동한다. 앱이FFmpeg를자동설치하지 않는다. CI에서만 runtime을 준비한다.

기존단일작업잠금은SD/Krea/Wan/tools모두공유한다. Comfy prompt UUID를제출전저장하고unknown시재제출하지않는다. 취소는기존scoped API만사용한다. FFmpeg local작업및제출전미디어준비는별도AbortController로종료한다. 앱재시작시local미완료작업은실패안내하며자동재실행하지않는다.

Comfy 업로드에는새로운 rgdqwer_UUID 파일만쓰고응답name/subfolder/type이일치해야한다. 기존파일덮어쓰기없음. Comfyinput에남는앱파일의수동정리법을문서화한다. 브라우저재생은인증된artifact fetch→blob URL,media-src self/blob만,CSP유지.

## UI와 프롬프트

전용영상화면: 생성/변환모드,로컬원본파일,주체/장면/움직임/속도/카메라/배경변화/분위기/시작종료8개필드,수동편집가능최종prompt,해상도/frames/FPS/seed/denoise,진단및미리보기. 규칙기반한국어키워드변환의한계를명시한다. I2V조합은외형보존과움직임/카메라중심문구를쓴다. Image to Prompt의편집문장을그대로전달하고자동생성하지않는다. 결과MP4재생/다운로드,추출PNG,작업기록재사용은원래영상화면으로복원한다.

## 검증

실제 FFmpeg 합성 테스트클립의 업로드→변환/보간/업스케일/추출→ffprobe·전체디코드/브라우저재생을 검증한다. 합성입력임을명시하고 실제AI영상으로주장하지않는다. Wan 그래프/HTTP/모델누락/취소/복구는 fixture와공식소스계약으로검증하며 실제모델/GPU생성은미검증게이트. 실제CPU변환성공은실제변환검증으로기록한다.
