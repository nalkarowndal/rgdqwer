**Goal:** Reproducible Windows installer, packaged runtime validation and repeatable stability reports without overstating device acceptance.
**Architecture:** Keep Electron/React/Fastify; electron-builder packs allowlisted JS/UI and external Python sources. Isolated smoke/soak tooling validates real file/database lifecycles using a clearly simulated engine.

**Spec:** docs/superpowers/specs/2026-10-25-m8-release.md

## Global Constraints
- Windows x64, appId io.github.nalkarowndal.rgdqwer, product rgdqwer, version0.9.0; preserve userData/studio.
- Per-user NSIS, no elevation/autostart, preserve data on uninstall; publish never; unsigned testing artifact, no release.
- No bundled models/Comfy/Git/FFmpeg/Python interpreter; optional Worker sources outside ASAR.
- Allowlisted payload; exclude tests/caches/.env/data/models/history. Package production dependency license inventory and SHA256 manifest.
- Soak default >=180s/100cycles; CI >=20s/20cycles; max1h/2000cycles; heap128MiB/RSS256MiB diagnostic growth thresholds after warmup, no leak-proof claim.
- One final fresh reviewer, inline implementation, no independent implementation agents.

## Review Focus
- Installed runtime must not depend on source cwd or attempt Python execution inside ASAR (Task1/2).
- Packaging must not include user models, tokens, test data or development dependencies (Task1).
- Installer/reinstall/uninstall tests must not touch an existing user installation/profile (Task2).
- Repeated jobs/restarts/cancellation must release sockets, processes and temporary files without corrupting history (Task3).
- Finite simulated soak and hosted Windows checks must never imply real GPU, clean-client, signed-release acceptance (Task3/4).
