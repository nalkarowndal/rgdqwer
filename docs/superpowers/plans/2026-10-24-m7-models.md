# M7 Model Manager Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Explicit, integrity-checked local model and node management integrated with generation, library and memory controls.
**Architecture:** Existing Node/Fastify/sql.js owns assets and maintenance tasks; generation uses the same lock. React offers inventory, install/path/node controls and paged library.
**Tech Stack:** TypeScript/React/Fastify/sql.js, Node streams/HTTPS/Git, existing Comfy adapters.
**Spec:** docs/superpowers/specs/2026-10-24-m7-models.md

## Global Constraints
- Preserve old jobs/settings. DB v6. No automatic executable/model downloads or Python dependency installation.
- User-confirmed install/delete/activation. Owned assets only; source SHA256 and exact bytes for downloads.
- Max file 64GiB, node pack 256MiB/10000 entries; inventory depth8/10000 entries.
- HTTPS public destinations only, same policy after redirects; no proxy bypass. No overwrite/symlink escapes.
- All writes and memory release share generation maintenance exclusion. Historical reference acknowledgement.
- Estimates are not GPU measurements; /free is asynchronous; actual inference remains unverified.

## Review Focus
- Redirect/DNS/private-address and symlink/path-swap attempts must not write outside owned roots (Tasks 1/2).
- Partial downloads, disk failures, cancellation and restarts must not leave install success or destructive cleanup (Tasks 1/2).
- Configuration/root changes must preserve old assets and generation references (Tasks 1/3).
- Node code must never run during staging or dependency inspection; altered trees must not be silently deleted (Task 2).
- Old histories, paged favorites and generation during maintenance must remain correct (Tasks 1/3/4).
