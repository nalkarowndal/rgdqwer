# 기능별 모델 다운로드

사용자 요청: 캡처처럼 앱 안에서 기능을 체크하고 필요한 모델을 직접 다운로드한다. 기존 모델 관리자의 URL/바이트/SHA256 수동 입력을 기본 흐름에서 제거한다.

## 결정

기존 다운로드/취소/소유 파일 저장/생성 잠금 위에 큐를 붙인다. 별도 모델 마켓이나 실행기 설치기를 만들지 않는다. 목록은 현재 구현된 SDXL 이미지, Krea2 Turbo/RAW, Wan2.2 5B 영상, Florence2 이미지 설명, WD14 태그, Chatterbox 다국어 TTS/VC를 제공한다. 캡처의 LLM/MiniMax/Anima 엔진은 현재 지원되지 않으므로 목록에 표시하지 않는다.

공식 제공자/Comfy-Org와 기존 Worker가 요구하는 명시적 파일만 받는다. 서버 내장 카탈로그가 repository/path를 결정하며 클라이언트는 featureIds와 사용 권한 확인만 전달한다. Hugging Face 메타데이터에서 commit SHA, 크기와 LFS SHA256을 얻는다. 일반 Git 파일은 제한된 크기로 읽고 Git blob SHA1 검증 후 SHA256을 계산한다. 요청 안에서는 모든 URL을40자리 commit에 고정한다. 부분 설치 재시도는 이미 받은 같은 저장소의 commit을 유지한다. 코드나 임의 저장소 파일은 실행/설치하지 않는다.

여러 기능의 공통 파일은 한 번만 받으며 이미 검증해 등록한 파일을 재사용한다. 한 번에 한 파일씩 다운로드; 총 진행률/현재 파일/취소/실패 이유를 기존 설치 기록에 표시한다. 완료한 파일은 취소/실패/재시작 뒤 보존하고 재선택 시 누락분을 받는다. 중단된 파일은 처음부터 다시 받는다. 파일 크기/해시 불일치, 디스크 부족, 경로 충돌은 명확히 실패하고 기존 파일을 덮어쓰지 않는다.

준비 상태는 현재 관리 폴더의 파일 존재/크기/일관된 revision을 검사한 **모델 파일 준비**이다. ComfyUI 경로 설정/재시작, 별도 Python 환경/Worker 경로와 실제 GPU 호환성은 별도 안내한다. 메타데이터 조회 전 용량은 약값이며 실제 총 다운로드 크기는 작업 시작 후 계산한다. 서버에서 선택한 묶음을 위한 여유 공간을 확인한다. 설치된 파일의 전체 해시는 재사용 직전에 다시 확인한다; 상태 폴링은 대용량 파일을 해시하지 않는다.

Windows 실행형 ZIP과 설치형에 포함한다. 기존 라이선스 확인 UI와 HTTPS/DNS/프록시 제한을 유지한다. 실제 대용량 모델/GPU 추론을 검증했다고 주장하지 않는다.

## 검증

메타데이터/commit/해시 검증, 공통 파일 중복 제거, 다중 파일 설치와 취소 후 재시도, 디스크/손상/충돌, 인증/잘못된 선택, 재시작 기록, UI 체크/진행/오류/모바일 접근성을 검사한다. 다운로드 수명주기는 실제 파일/DB와 주입한 작은 HTTPS 응답 fixture로 검사하며 운영 경로에 fixture 옵션을 노출하지 않는다. Windows CI에서 실제 공개 카탈로그 메타데이터와 소형 설정 파일을 확인하고 8MiB 이하 구성 파일 두 개를 실제 다운로더로 받아 검증한다. 다GB 가중치는 자동으로 받지 않는다.
