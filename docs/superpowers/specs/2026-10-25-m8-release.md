# M8 Windows packaging and stability verification

Implements REQUIREMENTS.md M8 and §15 on the existing Electron/React/Node/Python architecture. Continue the established inline execution and draft-PR workflow; the user has repeatedly requested direct execution of the supplied master requirements. Choices below are implementer decisions, not newly solicited user preferences.

## Approach

Use electron-builder 26.18.0 with the existing Electron entry and a per-user x64 NSIS installer. Forge would require changing the established build flow; a ZIP alone would not satisfy the installer requirement. Package the app and production Node dependencies in ASAR, unpack WASM, and place Python Worker sources and user documentation in extraResources. No models, Python environments, ComfyUI, Git or FFmpeg binaries are bundled or downloaded by the installer. This keeps optional engines/license environments explicit; setup remains manual.

App identity `io.github.nalkarowndal.rgdqwer`, product/executable `rgdqwer`, version0.9.0. One-click current-user install, no elevation, no automatic launch, preserve user data on uninstall, stable application identity for upgrades. Build with `--publish never`; never create a public GitHub release or claim a signed build. No certificate is available: unsigned testing artifacts and SHA256 only, with signing/SmartScreen and real Windows client gates documented. x64 Windows10/11 are the intended targets; hosted Windows CI is not a clean client/device acceptance test.

## Runtime and payload

Production entry remains dist/desktop/main.js; UI/API code must start from ASAR with sql.js WASM available. An explicit runtime-resource setter resolves voice_worker/runner.py outside ASAR for Python; development paths remain supported. Worker/model execution is opt-in and retains existing isolation and permissions. Preserve the existing userData/studio location. Honor an explicit absolute --user-data-dir for isolated package validation and user-selected profiles; never point QA at an existing personal profile. Record/validate isolation in the test runner.

Allowlist packaged build files and Python *.py/requirements*.txt, excluding tests, caches, .env, data, models and repository history. Generate production dependency license inventory and SHA256 artifact manifest; include Electron's packaged notices. Do not invent an application open-source license or signing identity. Installer payload inspection must verify required files and reject accidental source/data/secret inclusion.

## Packaged validation

Build an unpacked Linux app locally for executable smoke. Windows CI builds NSIS, silently installs into an owned disposable directory, launches the installed executable, checks Electron security preferences/packaged resources, saves settings/imports a small fixture, closes/restarts and confirms persistence, runs packaged Python status without claiming inference, repeats install as an upgrade, and uninstalls while verifying the isolated user data survives. Installer test refuses non-CI execution and existing installation registration; never uninstalls an unrelated app. Keep generated artifact/report paths in release/ and test-results/.

## Stability and UI verification

A repeatable Node API soak uses the explicitly simulated Comfy engine, actual local file import/hash/delete, real saved PNG validation, library favorites and repeated close/reopen. It exercises cancellation and maintenance exclusion; all children, WebSockets and temporary directories must close. Default extended run: at least180s and100 cycles; CI short run: at least20s and20 cycles. Bound inputs (duration<=1h, cycles<=2000) and record elapsed time/cycles/restarts, heapUsed/RSS samples, active resources and final engine connections. Measure after warmup and optional exposed GC. Default diagnostic growth thresholds: heap128MiB/RSS256MiB, with honest finite-run language; passing is not proof of no leaks or GPU stability. Long real-model/GPU sessions remain a documented target-device gate.

Keep browser coverage across all studios and add keyboard/responsive/navigation checks as needed. Run existing JS/Python/browser suites, build, desktop and Python HTTP smoke. User guide documents install prerequisites, model/engine setup, data paths, backup/restore with the app stopped, upgrade/uninstall behavior, missing dependency recovery and known limitations. No automatic updater, telemetry or public publication.

## Acceptance and review

Evidence must separate local/hosted CI, packaged app, synthetic media/simulated engine and real-device gates. A single fresh final reviewer examines packaging allowlists, resource paths, installer ownership and retention, lifecycle cleanup and memory conclusions. Fix Important/Critical once with regressions, then create draft PR over M7 and inspect final Windows/Linux CI plus installer artifact checks. Full M8 clean-Windows/real-model acceptance remains withheld until target-device and signing gates are met.
