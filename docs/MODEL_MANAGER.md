# 모델·확장 관리자 (M7)

**기능별 다운로드**에서 이미지·Krea·Wan·분석·음성 모델을 체크하고 한 번에 받을 수 있습니다. [선택·취소·재시도·엔진 연결 안내](FEATURE_MODEL_DOWNLOADS.md)를 먼저 확인하세요. 아래 수동 가져오기/다운로드도 계속 사용할 수 있습니다.

v0.8.0은 체크포인트, LoRA, VAE, 텍스트 인코더, 분석·영상·음성 모델을 명시적으로 가져오거나 다운로드하고 관리한다. 실제 모델/GPU 검증은 별도이며 M7 실기 통과를 선언하지 않는다.

## 모델 추가

1. 모델 추가에서 종류·호환 계열·파일 이름·출처·버전·라이선스를 기록한다. 추정 VRAM은 선택이며 실측값과 구분한다. 필수 모델 ID와 ComfyUI 노드 이름을 쉼표로 입력할 수 있다.
2. 가져오기는 Node 서버가 읽을 수 있는 원본 **절대 경로**를 입력한다. 원본은 보존하고 관리 폴더에 복사한다. Renderer에는 범용 파일 읽기 API를 노출하지 않는다.
3. 다운로드는 공개 HTTPS 443 주소, 정확한 바이트 수, 제공자 SHA256을 요구한다. 로그인·프록시 환경은 직접 다운로드 후 가져오기를 사용한다. 프록시를 우회하지 않는다. 모든 리디렉션/DNS 주소를 검사하고 연결 IP를 고정한다. URL의 인증 정보와 사설/예약 주소를 거부한다.
4. 출처·라이선스·사용 권한을 확인하고 시작한다. 진행률, 취소, 실패 원인을 설치 기록에서 확인한다. 재시작 후 중단된 설치를 자동 재제출하지 않는다.

64GiB 파일 상한, 디스크 여유 64MiB 이상의 사전 검사, 스트리밍 SHA256, 정확한 크기 검사, 대상 볼륨 임시 파일과 원자적 비덮어쓰기 커밋을 사용한다. 대상 폴더가 하드링크를 지원해야 한다(NTFS 권장). 모델 내용은 가져오기 과정에서 실행하지 않는다. 체크섬은 제공자의 안전성이나 모델 호환성을 보증하지 않는다. 신뢰하는 모델만 실행한다.

단일 파일은 UUID 접두사를 사용한다. 여러 파일을 요구하는 분석/음성 모델은 같은 **번들 이름**에 각각 원래 파일명으로 등록한다. 존재하는 파일은 덮어쓰지 않는다. 분석·음성 Worker 환경 변수는 [이미지 분석](IMAGE_TO_PROMPT.md)과 [음성 시스템](VOICE_SYSTEM.md)을 참고해 실제 번들 경로로 수동 설정한다. 해당 문서가 명시한 정확한 모델 파일 세트를 모두 준비해야 한다.

## 경로와 호환성

기본 경로는 앱 데이터 폴더의 `models`다. 경로·메모리에서 새 절대 경로를 지정하면 이후 설치 위치만 바뀐다. 이전 파일과 소유 기록은 유지한다. 관리 드라이브가 끊기거나 경로를 읽을 수 없어도 앱과 라이브러리는 시작하며 경고를 표시한다. 경로 설정에서 복구할 수 있다. 설정 화면의 기존 참조용 경로는 이 관리 경로와 별개다.

경로 설정 생성 결과를 `rgdqwer-model-paths.yaml`로 저장한다. ComfyUI 실행에 `--extra-model-paths-config /absolute/path/rgdqwer-model-paths.yaml`을 추가하거나 기존 extra-model-paths 설정에 병합한 후 **재시작**한다. 생성된 YAML은 현재/이전 관리 루트와 앱의 custom_nodes 경로를 포함한다. 앱은 기존 ComfyUI 설정을 덮어쓰거나 엔진을 재시작하지 않는다.

호환성 진단은 파일 존재·크기, 등록된 필수 모델, 엔진 노드 목록과 모델 로더 목록을 확인한다. 계열·라이선스·필요 VRAM은 사용자가 등록한 값이며 자동 식별이 아니다. 엔진에서 발견되어도 추론 성공이 보장되지 않는다. `sd15`/`sdxl` 체크포인트는 생성 화면에서 선택할 수 있다. 다른 종류는 해당 스튜디오 또는 Worker 설정에서 선택한다.

관리 폴더의 등록되지 않은 파일은 읽기 전용으로 표시한다. 탐색은 깊이 8/항목 10000으로 제한한다. 심볼릭 링크·junction 경로를 거부한다. 동일 사용자 권한의 악성 로컬 프로그램과 파일시스템 경합까지 격리하는 보안 경계는 아니다.

## 삭제·충돌 방지

관리 파일 삭제와 기존 작업 재생성 영향 확인을 모두 선택해야 삭제한다. 서버도 과거 작업 참조를 확인한다. 다른 관리 모델의 필수 의존성은 삭제를 차단한다. SHA256/크기가 설치 기록과 다른 파일은 삭제하지 않는다. 원본·미등록 파일·작업 결과는 삭제 대상이 아니다. 삭제·비활성화 의도를 DB에 먼저 저장하고 파일 정리 후 소유 기록과 의도를 함께 확정한다. 확정 저장이 실패하면 미완료 기록을 표시하고 신규 생성을 차단한다. 디스크/경로를 복구한 뒤 같은 작업을 다시 요청하거나 앱을 재시작하면 재검증 후 정리한다. 중간에 변경된 파일은 보존하며, 부분 파일시스템 실패로 변경된 폴더가 남으면 수동 검토 후 정리해야 한다.

앱의 생성 작업과 모델 설치/제거/경로/노드/메모리 변경은 공유 잠금을 사용한다. ComfyUI 큐가 바쁘거나 유효한 유휴 응답을 확인할 수 없으면 변경을 차단한다. 연결 거부로 엔진이 꺼진 경우에는 로컬 파일 관리를 허용한다. 다른 ComfyUI 클라이언트가 큐 확인 직후 제출하는 경합까지 원자적으로 막을 수는 없으므로 관리 중 외부 클라이언트는 사용하지 않는다.

## 커스텀 노드

Git이 설치되어 있어야 한다. GitHub HTTPS 저장소와 정확한 40자리 커밋을 입력하고 위험을 확인하면 `node-staging/<id>`에 소스를 준비한다. Git hooks/전역 설정/checkout 필터·서브모듈·pip 설치를 실행하지 않는다. 요구사항·라이선스를 읽고, 표시된 경로에서 코드를 직접 검토한다. 의존성 문서는 최대 64KiB/파일, 소스는 256MiB/10000항목으로 제한한다. Git 작업 폴더는 100ms 간격으로 512MiB를 검사하며 순간적인 초과 가능성이 있다. Git 요청은 120초 후 중단한다.

검토와 의존성 준비를 별도로 확인하면 앱의 `custom_nodes/<id>`로 복사하여 활성화한다. 필요한 의존성은 **ComfyUI의 올바른 Python 환경**에서 사용자가 설치한다. 활성화된 코드는 ComfyUI 재시작 시 임의 코드를 실행할 수 있다. 비활성화/삭제 후에도 이미 로드된 코드는 재시작 전까지 남는다. 변경된 소스/활성 트리는 자동 삭제하지 않는다. 사용자가 추가한 루트/중첩 .git 기록은 활성화와 삭제를 모두 차단한다. 정상 형식의 __pycache__/*.pyc는 런타임 캐시로 제외하되 링크·비정상 캐시 항목은 거부한다. 노드에 선언되지 않은 런타임 의존성은 정적 검토만으로 보장하지 않는다.

## 라이브러리·메모리

모든 저장 작업을 20개씩 조회하고 프롬프트·모델·시드·제목을 검색한다. 종류/즐겨찾기 필터, 제목 저장, 2–4개 결과·설정 비교, 다운로드와 설정 재사용을 지원한다. 재사용은 입력을 복원하며 자동 생성하지 않는다. 이전 SQLite 데이터를 보존해 DB v6으로 올린다.

유휴 VRAM 해제는 `/free`에 `unload_models=true, free_memory=true`를 보내는 **비동기 요청**이다. 요청 접수 후 메모리 상태 새로고침으로 실제 여유량을 확인한다. 8GB GPU 성능·최고 VRAM·오프로딩·메모리 누수 검증은 실기 과제다.
