# M4 최종 리뷰와 결정 기록

범위: M3 `41df5a52` → M4 `24515638`.
독립 fresh-context 리뷰: gpt-6-astra (`m4_review`), 읽기 전용.
Critical/Important 없음. 리뷰어는 전체 테스트를 재실행하지 않았고 공식 소스 비교와 진단 조건의 집중 재현을 수행했다.

## 확인과 유예

TextGenerate의 dynamic input 키, PreviewAny의 text history 계약, RAW CFG/shift 변환,
확장 후 LoRA 트리거 결합, 제출 전 모델 목록 재검사, SD/Krea 공유 잠금과 화면 복원을 확인했다.

**유예 Minor 1건:** ConditioningZeroOut를 모든 Krea 프로필의 필수 노드로 검사한다.
RAW 그래프는 빈 CLIP negative를 사용하므로 이 노드가 없어도 원리상 실행할 수 있지만 현재 진단은 RAW도 차단한다.
리뷰어가 해당 노드만 목록에서 제거해 rawGraphUsesZeroOut=false와 preflight error를 재현했다.
표준 ComfyUI에는 있는 core node이고 출력 오염·소유권 손상은 없으므로 경미한 과잉 검사로 분류했다.
후속 정리: Turbo 전용 의존성으로 분리하고 RAW에서 해당 노드가 없는 회귀를 추가한다.

## 실행 중 결정과 비용

1. 기존 전용 클라우드 체크아웃에서 새 M4 브랜치로 진행했다. 의존성 복제를 피하지만 다른 브랜치를 같은 디렉터리에서 동시에 편집할 수 없다.
2. 공식 RAW 코드를 근거로 CLI CFG3.5를 ComfyCFG4.5로 변환하고 해상도별 mu를 적용했다. 수학적 대응과 소스 계약은 확인했지만 실기 품질/수치 오차 검증은 남는다.
3. 공식 샘플링의 minres256/maxres1280과 cond 기반 CFG 정의를 다시 확인하고 위 결정을 유지했다. standalone과 동일 픽셀을 보장하지 않는다.
4. 엔진 확장 결과를 PreviewAny로 보존하도록 설계를 보완했다. 실제 문장을 확인할 수 있지만 core node 및 text history 계약이 추가로 필요하며 없으면 제출을 차단한다.
5. 모델/GPU 없는 클라우드에서 모의 QA와 실기를 분리했다. 실제 Windows/GPU에서 호환성·품질·성능 수정이 필요할 수 있다.

## 리뷰가 판정하지 않은 항목과 처리

- 실제 RAW/Turbo·한국어 확장 품질·LoRA·2K: 가중치/GPU 부재. 코드 검토로 추론 완료를 주장하지 않고 수동 게이트 유지. 실기에서 오류/품질 문제가 발견될 수 있다.
- RTX2060SUPER8GB·오프로딩 성능·메모리 충분성: fixture/소스로 확정 불가. 화면에 미검증·측정값·준비 안내를 제공하며 지원/불가 어느 쪽도 단정하지 않는다. 실제 OOM이나 과도한 지연 가능성이 남는다.
- 실제 Windows/GPU 취소·재시작: 모의검증을 넘어 판정하지 않음. 기존 scoped cancel/UUID 추적을 유지하고 실기 게이트로 남긴다. 사용자 엔진 버전에 따른 추가 대응이 필요할 수 있다.
- standalone RAW 픽셀 동일성: CFG/shift 수학만 검증. 네이티브 Comfy 어댑터이며 동일 픽셀 재현을 약속하지 않는다. 엔진 구현/정밀도 차이에 따른 결과 차이는 남는다.
