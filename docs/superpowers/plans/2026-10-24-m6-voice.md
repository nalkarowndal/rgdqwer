# M6 Voice Studio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Local TTS and voice conversion with reusable authorized voice profiles and recorded/uploaded sources.
**Architecture:** Existing authenticated Node API and durable job lock own isolated Python inference children; FFmpeg normalizes and validates audio. React provides profiles, recording, playback and comparison.
**Tech Stack:** React/TypeScript/Fastify/sql.js, Python, Chatterbox, rvc-python, FFmpeg.
**Spec:** docs/superpowers/specs/2026-10-24-m6-voice.md

## Global Constraints
- ko/ja/en; TTS <=3000 characters, chunks <=180 Unicode code points.
- Upload <=16 MiB / 60s / 48kHz / stereo; reference 3–30s; output <=600s.
- RVC pitch -12..12; no unsupported Chatterbox pitch. WAV/MP3 exports.
- Independent Python environments; no automatic downloads; preserve watermark.
- One GPU job; explicit consent; retain historical settings; actual inference acceptance pending.

## Review Focus
- Forged or truncated audio headers and decode expansion must not bypass limits (Task 1).
- Revoked/deleted profiles or missing assets cannot authorize new conversion (Task 2).
- Cancellation/process failure must clean partial artifacts and release lock after exit (Task 2).
- Late microphone permission and navigation must not leave live tracks (Task 3).
- Old DB jobs and non-audio UI must retain their behavior (Tasks 1/3).
